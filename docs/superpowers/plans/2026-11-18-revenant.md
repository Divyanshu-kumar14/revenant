# Revenant Implementation Plan

> **For agentic workers:** this harness has no `superpowers:*` sub-skills. Execute tasks natively in this session, or dispatch one `general` subagent per task with this plan and the task's Interfaces block. Steps use `- [ ]` for tracking.

**Goal:** Ship a working, deployable archive tool that turns photographs of unidentified collection items into reviewed, searchable, citable records, built in public with Kiro.

**Architecture:** A single Next.js application (App Router) with server-side route handlers, a SQLite database accessed through `node:sqlite`, local file storage for images, and a queue table processed by an in-process batch runner. All model access sits behind an `Extractor` interface so tests and the demo can replay recorded fixtures with no network. Review is mandatory before publication; every decision writes an audit event.

**Tech Stack:** Node 26, pnpm 10, Next.js 16 (App Router), React 19, TypeScript strict, Tailwind 4, `node:sqlite`, `zod`, `sharp`, `fast-check` (PBT), Vitest, Playwright, Docker on Render with a persistent disk.

**Spec:** `docs/specs/revenant.md`

## Global Constraints

- Node `26.x`, pnpm `10.x`; package manager is pnpm, lockfile committed.
- TypeScript `strict: true`; no `any` in exported signatures.
- Database is SQLite through `node:sqlite` (`DatabaseSync`), WAL mode, migrations idempotent.
- Images are stored at `$REVENANT_DATA_DIR/uploads/<sha256>.<ext>`; DB at `$REVENANT_DATA_DIR/revenant.db`; default `./data`.
- All model calls go through `Extractor`. Unit tests never hit the network.
- Public pages are unauthenticated. `/admin/**` and `/api/admin/**` require a signed cookie derived from `ADMIN_PASSWORD`.
- Every item carries provenance: `sha256`, `file_name`, `model`, `created_at`, and a rights line.
- `.kiro/**` is committed and must never appear in `.gitignore`.
- MIT license file at repo root; license visible in GitHub About.
- No invented metrics. Every number in README, video or submission is traceable to `eval-runs/*.json`.
- Conventional commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
- After every task: tick the matching item in `.kiro/specs/<feature>/tasks.md`, append one line to `docs/kiro-log.md`, run `pnpm typecheck && pnpm test`, commit.

## Review Focus

These are the failure modes no single task's happy path covers. Each is pinned to a test in the task that owns the code.

1. **Ambiguous or partial dates** — "circa 1900", "Summer 1938", "12/25/38", "before the war" must never be turned into false precision; `start <= end`; unknown input yields nulls, not today's date. → T4.
2. **Unicode names** — "Müller", "Škoda", "O'Brien", "李 小龙" must survive normalisation intact and normalise idempotently; no diacritic stripping. → T4.
3. **Re-ingest of identical bytes** — the same photograph uploaded twice must yield one item, one set of entities, and an audit event, never a duplicate. → T2.
4. **Extractor failure or malformed output** — timeout, non-JSON, or schema-invalid JSON must leave the item in `needs_review` with an error and no published record; nothing is lost or silently published. → T5.
5. **EXIF-rotated and oversized images** — a 12 MP phone photo rotated by EXIF must be stored upright and downscaled below the model limit without OOM. → T2.

`ProviderExtractor` posts a base64 image plus the prompt to `${VISION_BASE_URL}/chat/completions` with `response_format: { type: "json_object" }`, a 30 s `AbortSignal.timeout`, one repair retry on schema failure, and `zod` validation of the response.
